# Дизайнер квестов

## Формула хорошего квеста

1. **Крючок** (1 фраза NPC): личная проблема, а не «убей 10 крыс». *«Мой сын ушёл в лес и не вернулся».*
2. **Подготовка** (1–2 цели): исследовать, собрать, починить — знакомит с местом и механикой.
3. **Кульминация**: бой, выбор или открытие.
4. **Развязка у NPC**: награда + новая грань лора (каждая сдача что-то рассказывает).
5. **След**: квест меняет мир (зажжённые тотемы, починенные громоотводы, ослабленный босс, новая реплика NPC).

Сюжетная арка — три акта: *пробуждение (обучение, ур. 1–5) → открытый мир с параллельными целями → схождение к финалу с выбором*. Каждый регион Акта II строится одинаково: **хранитель знаний → подготовка → босс → возвращение**.

## Где что лежит

| Что | Файл |
|---|---|
| Определения квестов | `game/src/data/quests.js` |
| Реплики NPC (выдача, прогресс, сдача) | `game/src/data/dialogues.js` (навык `dialogue-writer`) |
| Квестовые объекты, лагеря, боссы, точки | `game/src/data/locations.js` |
| Логика квестов | `game/src/systems/quests.js` |

| Сюжет целиком | `game/docs/STORY.md` |

## Формат квеста

```js
my_quest: {
  kind: 'side',            // main | side
  act: 2,                  // только для main
  name: 'Название',        // 1–3 слова, без кавычек
  giver: 'npc_id',         // кто выдаёт (маркер «!» над головой для side)
  level: 8,                // рекомендуемый уровень; также уровень сгенерированных наград
  req: { quest: 'mq2' },   // когда доступен: после выполнения; { quest, state: 'active+' } — после начала
  summary: 'Абзац для журнала: кто, что случилось, почему это важно.',
  objectives: [            // выполняются строго по порядку
    { type: 'talk', target: 'npc_id', text: 'Поговорить с …' },
    { type: 'reach', x: 0, z: 0, r: 20, text: 'Добраться до …' },
    { type: 'kill', target: 'enemy_type', count: 6, text: 'Убить …' },
    { type: 'boss', target: 'boss_id', text: 'Победить …' },
    { type: 'collect', target: 'item_id', count: 4, consume: true, text: 'Собрать …' },
    { type: 'interact', target: 'object_kind', count: 3, text: 'Зажечь …' },
    { type: 'waystone', target: 'ws_id' }  /* или count: 8 */,
    { type: 'tablets', count: 7 }, { type: 'shards', count: 5 },
  ],
  turnIn: 'npc_id',        // null — квест закрывается сам после последней цели
  rewards: { xp: 700, gold: 110, items: [{ id: 'potion_hp', n: 2 }], gen: [{ slot: 'hands', rarity: 2 }], unique: 'u_id', skillPoints: 1, flag: 'alchemy' },
  next: ['quest_id'],      // стартуют после сдачи
  start: ['quest_id'],     // стартуют одновременно с этим квестом (параллельные цепочки)
},
```

Особенности движка:
- `talk` закрывается только действием в диалоге `g.advance('quest_id')`.
- `collect` считает предметы в сумке; `consume: true` — предметы забираются при следующем `talk` этого квеста или при сдаче.
- `interact` засчитывается квестовыми объектами из `QUEST_OBJECTS` с полем `kind`; объект активен (подсказка «E»), только пока текущая цель его ждёт.
- Предметы-трофеи для `collect` задаются в `drops` врага (`src/data/enemies.js`) — трекер сам покажет ближайший лагерь.

## Награды (ориентиры)

- Опыт за квест ≈ 0,5–0,7 от `xpCurve(level)` для побочного и 1–1,5× для сюжетного. Посчитать: `node game/tools/balance.mjs`.
- Золото ≈ `level × 12…20`.
- Снаряжение: `gen` с редкостью 1–2 для побочных, 2–3 для сюжетных; уникальный предмет — за длинную цепочку или коллекцию.
- Очки навыков — редко (1–2 за игру), только за ключевые сюжетные вехи.

## Внедрение — шаги

1. Опиши квест в `docs/STORY.md` (таблица акта или побочных).
2. Добавь объект в `QUESTS`.
3. Добавь узлы в диалог выдающего NPC: `offer` (с `g.start`), `wait`, `done` (с `g.turnIn`), и поправь `start(g)`, чтобы узлы выбирались по `g.state(...)`, `g.can(...)`, `g.at(...)`.
4. Нужны новые объекты/лагеря/точки — добавь в `src/data/locations.js` (см. `world-builder`).
5. Босс с подготовкой — допиши условие в `_shieldFor`.
6. Проверь: `cd game && npm run dev` (порт 5173), затем `node tools/quest-test.mjs` — прогоняет весь сюжет через настоящие диалоги. Для нового квеста добавь шаги в тест по образцу региональных.

## Чек-лист

- [ ] У каждой цели есть понятное `text` с направлением («к северо-западу», «у маяка»).
- [ ] Игрок знает, куда идти: цель имеет точку (NPC, лагерь, объект, координаты) — иначе трекер не покажет маркер.
- [ ] Диалог выдачи объясняет «почему», сдачи — даёт новую деталь лора.
- [ ] Нет тупиков: квест можно завершить, даже если игрок убил босса раньше (движок засчитывает уже мёртвых боссов и уже собранные предметы).
- [ ] Автотест проходит.
